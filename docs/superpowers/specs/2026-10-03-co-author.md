# Co-author: spec (v0.1)

Date: 2026-10-03. Harness: Claude (planner). Status: approved by brief, ready for implementation.

## One line

A local-first collaborative editor where the AI is just another CRDT peer, and it can only **propose**: its edits arrive as tracked suggestions that a human accepts or rejects. The model proposes, the deterministic core disposes.

## Audience and purpose

Portfolio project #5 for a senior frontend engineer (React, TypeScript). Readers are recruiters and hiring engineers. They need a 30-second wow (GIF at the top of the README), a headline number that was measured, and proof of senior work (tests, ADRs, diagram).

## Goals (v0.1)

1. Rich-text editor (ProseMirror) bound to a Yjs document via y-prosemirror.
2. Persistence in IndexedDB (y-indexeddb). Works offline and installs as a PWA.
3. Cross-tab peer sync over BroadcastChannel (required baseline). No server needed.
4. An AI peer: a separate `Y.Doc` with its own client id and awareness identity (name, color, caret). It writes **only** into a suggestions layer (`Y.Map` named `suggestions`), anchored with Yjs `RelativePosition`s.
5. A fail-closed gate between the AI peer and the human document: any AI update that would change anything other than valid entries of the suggestions map is rejected, and the AI peer is quarantined.
6. Suggestions render inline as tracked changes (struck original + ghost insert) and in a Proposals panel, with accept and reject. Accept applies the edit as a normal, undoable Yjs transaction.
7. AI backends: an OpenAI-compatible streaming endpoint (default Ollama at `http://localhost:11434/v1`, reached through the same-origin proxy path `/ollama/v1` to avoid CORS; model `qwen3.8:27b`) and a deterministic mock model for demos and tests.
8. Measured numbers in the README: convergence time across N simulated peers, offline divergence merge time and size, gate overhead, cross-tab latency over BroadcastChannel in Node.

## Non-goals (v0.1)

- Multi-block suggestions, lists, tables, images, hard breaks (flat schema: heading and paragraph text blocks only, see ADR 0001).
- Accounts, sharing links, application servers. The y-websocket relay is optional (Docker profile), BroadcastChannel is the baseline.
- Gating updates from remote human tabs (the trust boundary is the tab hosting the AI peer, see ADR 0003).
- WebRTC across machines.

## Functional requirements

| ID | Requirement |
|----|-------------|
| F1 | Typing in the editor updates the Y.Doc; opening a second tab with the same `?doc=` shows the same content within one frame of the update being posted. |
| F2 | Reloading the page restores content from IndexedDB with no network. |
| F3 | "Simulate offline" disconnects cross-tab sync; edits made in both tabs while offline merge on reconnect, with no lost characters. |
| F4 | The user selects text (or places the caret in a block) and asks the co-author with a short instruction. The AI peer streams a draft that appears as a live ghost insert, then splits into word-level hunks. |
| F5 | Each hunk is a suggestion: struck original text inline, ghost insert after it, and a card in the Proposals panel. Accept and Reject work inline and from the panel. |
| F6 | Accept applies the hunk as one transaction (origin `co-author:accept`), undoable with Ctrl+Z. Reject removes it. Both record a resolution in the `resolved` map. |
| F7 | If the human edits text inside a suggestion's range before deciding, the suggestion shows as **conflict** and Accept is disabled. If the block is deleted, the suggestion becomes **orphan** and is hidden. |
| F8 | The AI peer has a visible identity: avatar in the peers list, a caret flag in the text while working, an activity label (idle, thinking, streaming). |
| F9 | Any AI attempt to write outside the suggestions layer is blocked; the UI shows a blocked counter, and a "Simulate rogue write" control demonstrates it. |
| F10 | The model backend is configurable (mock or OpenAI-compatible base URL, model, optional API key), stored in localStorage. `?ai=mock` forces the mock. |
| F11 | Late AI writes to an already resolved suggestion id are inert: filtered from every view and refused by accept, and the AI peer stops streaming once its draft is resolved. |
| F12 | `docker compose up` serves the built app on port 5175; `docker compose --profile relay up` adds a y-websocket relay on 1234. The app proxies `/ollama/*` to the host Ollama daemon (`localhost:11434` in dev, `host.docker.internal:11434` in Docker). |

## Invariants (each enforced by a test, see plan)

- I1 The AI peer can never change `prosemirror` (the text) or `resolved`, or create any other root type.
- I2 All peers converge to identical text and suggestion state after exchanging updates, regardless of order.
- I3 A suggestion's anchors survive concurrent human edits outside its range (they shift with the text).
- I4 Accept applies only when the current range text equals the suggestion's `original`.
- I5 Seeding is idempotent: applying the demo seed in any number of tabs never duplicates content.
